# 后台进程日志

- 点击侧边栏的后台进程，在当前对话的右侧打开日志标签页。同一进程重复打开复用标签页。
- 可见标签页在进程运行时串行查询，每次响应后等待一秒；切换、隐藏或关闭标签页停止查询，关闭标签页不停止进程。
- 默认跟随最新输出。向上滚动或点击“暂停跟随”保留当前显示；回到底部或点击“跟随输出”显示最新快照。暂停显示期间仍获取状态和最新快照。
- 进程结束后停止轮询并保留最终输出。读取失败保留已有输出，通过“重试”恢复。
- 复制针对当前显示内容。打开日志文件复用文件标签页。停止操作复用进程管理接口，不发送对话消息、不唤醒模型。

## 数据与生命周期

`ProcessRegistry` 是进程身份、对话归属、状态和日志路径的所有者。`ReadCommandOutput` 只接受对话 ID、进程 ID 及设备路由，不接受客户端提供的文件路径。查询在阻塞工作线程读取文件，不创建 Agent runtime。

已登记命令的 stdout 和 stderr 从启动时就共享日志文件的追加句柄。工具给模型返回的内容仍有大小上限，原始日志不被工具结果覆盖。进程日志位于数据目录 `command-processes/output/`，路径随进程记录持久化。

详情每次读取最后 8 KiB；跨 UTF-8 字符边界时跳过尾窗开头的不完整字符。进程结束后，日志及终态记录仍保存在磁盘，退出 live registry，详情可以继续读取。

管理器运行期间定期检查日志；当前文件超过 64 MiB 时，将末尾最多 8 MiB 保存至同名 `.previous.log`，然后截断当前文件。保持同一个文件对象，确保子进程已有的追加句柄继续有效；轮转过的详情显示保留范围提示。宿主被强制结束期间没有轮转线程，仍存活的服务可以继续写日志，恢复管理器后重新检查大小。服务自行重定向到其他文件的输出不在这个捕获范围内。

旧版本启动且没有日志路径的进程不能追溯补录历史输出；详情会显示读取失败。恢复及读取日志不重启进程，也不执行模型请求。

## 验证范围

- 文件尾窗、UTF-8 边界、轮转后已有追加句柄继续写入。
- 超过工具输出上限的日志仍可读取最新内容，stdout/stderr 合并，跨对话读取被拒绝。
- 终态输出在 live registry 移除及管理器重新打开后仍可读。
- 强制结束宿主后，存活服务继续写日志，新管理器可读取新增输出并手动停止服务。
- GPUI 标签页隐藏、关闭及迟到响应；冻结显示与恢复最终输出。
