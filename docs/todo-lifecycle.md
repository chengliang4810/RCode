# Agent 待办维护

## 状态来源

- 主 Agent 和每个子 Agent 使用自己的执行历史。最新一次成功的 `TodoWrite` 全量替换列表；失败、被拒绝和未完成的工具调用不改变有效状态。
- 提醒、普通结束检查和目标完成校验共用 `rcode_agent::todo::State`，不从摘要或用户文本猜测状态，不另建待办数据库。
- 完整压缩在摘要后、近期消息前放入被压缩前缀的结构化 checkpoint，保留列表、未完成原因和提醒计数，再按顺序重放近期消息。
- `/compact` 手动压缩通过 `ConversationTurn.todo_history_ids` 保留被排除条目组的本地引用。恢复时仅读取最新有效待办及后续提醒计数，不重新发送被排除的工具正文；旧会话缺少该字段时按原有方式读取。
- 内部提醒使用带 `Domain::Todo` 元数据的上下文消息，写入已有本地模型历史；不生成用户气泡或用户消息事件，不计为用户输入。旧历史仍可直接读取。

## 执行中提醒

- 当前工具集中有 `TodoWrite`，列表存在未完成项且没有显式未完成原因时才提醒。
- 距离最近成功更新至少 10 个 assistant 消息，且距离上次提醒至少 10 个 assistant 消息时，附当前有效列表提醒维护。
- 成功更新重置更新计数；提醒或结束检查重置提醒计数。完成、清空或显式记录未完成原因后不再周期提醒。

## 普通任务结束

- 自然结束且没有需等待的后台任务、协调消息或用户接管时，检查当前有效列表。
- 有未完成项且工具仍可用时，注入一次结束检查并继续当前执行；后续仍未处理则再次检查，不伪造完成状态。
- 确实无法继续时，通过 `TodoWrite` 的可选 `resolution` 记录 `{kind, reason}`：`kind` 为 `blocked`、`cancelled` 或 `scope_changed`，`reason` 必须非空。保留未完成状态，并向用户说明原因和剩余工作。
- 原因只针对这次完整列表；后续成功更新省略它，或收到新用户请求，重新进入正常检查。
- 没有列表、列表已完成或清空时正常结束。工具已不可用时不制造无法解除的普通任务循环。取消、失败、用户接管不强制续跑。

## 目标模式

- 普通结束检查与目标续跑互斥，每个结束点只有一条续跑决策。
- 校验器同时接收 `currentTodos` 和对话证据。最新有效列表覆盖旧列表和摘要；有 `pending` 或 `in_progress` 时不得通过，并给出最小可执行下一步。
- 即使模型误判通过，代码仍检查同一份列表，未完成则继续已有目标流程。
- 对未完成工作显式记录 `resolution` 后暂停目标并保留原因；不把阻塞、取消或范围变更当成完成证据。用户暂停、替换、停止和队列接管继续优先。

## 验证范围

`todo` 单元测试覆盖成功/失败写入、提醒间隔、序列化恢复、伪造文本、清空、原因校验及压缩；`todo_lifecycle` 集成测试覆盖真实循环中的提醒、结束续跑和阻塞反馈；`goal_mode` 覆盖校验输入、误判保护及目标暂停。
