# MCP、Agent 与 Client 复验

针对 `RCode-analysis.md` 的当前源码复验，2026-10-23。没有引入项目执行审批或内网访问限制。该产品的完全信任直接执行策略与缺陷修复分开处理。

| 项目 | 当前证据与处理 |
| --- | --- |
| H3 MCP 调用不响应停止、没有期限 | 成立。`mcp/src/tool.rs` 原先丢弃 ToolContext，`client.rs` 原先直接等待 SDK。现在传递取消令牌，工具调用限时 600 秒；取消/超时后取消服务并移除连接，报明结果可能不确定，禁止自动重放。下一次明确调用才可重连。 |
| H4 MCP 初始化无期限、重连占用连接锁 | 成立。原先握手及完整工具发现均无期限，重连跨 `open().await` 持有连接锁。现在整个初始化/工具发现限时 30 秒；重连由独立互斥锁串行合并，状态锁只用于短时间读取/发布连接。每个调用等待重连也限时 30 秒。stdio 在丢弃运输层时使用 SDK 的子进程清理。 |
| H5 项目 MCP 直接执行 | 行为成立，属于当前完全信任执行策略。未添加审批。只有 MCP 初始化时会启动配置的进程，纯文件浏览不在该调用链。 |
| M2 排队消息丢失 | 部分表述不准确：失败/停止没有立即清空队列，但原先显式恢复时用新 inbox 替换旧队列，确实丢失未读消息。现在 TaskOutput 的 `pending_messages` 显示尚未投递的该子任务消息；显式恢复按旧消息、新消息顺序投递，不因失败自动重启任务。未暴露完整历史。 |
| M3 事件消费者消失后仍运行 | 成立。原先 runner 分离 spawn，发送错误被忽略。现在接收端关闭时取消该运行专用的子令牌，并继续轮询原 future，允许工具完成异步清理；不会取消调用方的父令牌。 |
| M4 超时回收不受停止控制 | 成立。原先使用全新且永远不会被取消的令牌，最多再等 600 秒。现在复用前台 ToolContext 令牌，并传播取消。任务本身继续执行其进程回收。 |
| M9 WebFetch 能访问本地及内网 | 行为成立，属于当前完全信任工具边界，未添加地址限制。局部 HTTP 测试同时验证本地 URL 仍可访问。 |
| M13 WebFetch 读完整 body 后才检查 2 MiB | 成立。现在先检查声明长度，再分块读取并在追加前检查累计量；分块传输、未结束的响应也会在超限时终止。读 body 阶段继续支持取消。 |
| M19 异步交付循环同步执行 SQLite | 成立。扫描、恢复交付会话、收据/待发查询、条件完成收据均移到 `spawn_blocking`。保留版本条件与发出 wake 后再次检查 outbox 的顺序；不改变 ACK 语义。 |
| Agent 输出日志永不清理 | 成立。现在任务被淘汰或任务存储被释放时，任务 Drop 删除其拥有的输出文件；容量已满拒绝新任务时，也不再预先创建孤儿文件。历史运行已经遗留的日志未批量删除。 |
| agent_task_stores 无移除 | `harness/src/native.rs` 的会话级存储仍按会话保留；本轮没有增加容量及会话关闭回收策略，详见主复验记录。 |
| WebFetch 重复小写化导致二次方扫描 | 成立。每遇到 script/style 等隐藏块原先重新分配并折叠整个剩余文档。现在全文 ASCII 折叠仅一次，以等长字节偏移搜索；保留大小写与 Unicode 正文处理行为。 |
| Client checkpoint/rows 下载无大小上限 | 成立，`client/src/live/room.rs` checkpoint 使用 chunk 无限追加、rows 使用完整 bytes。未擅自规定协议大小：当前仓库没有远端 checkpoint 大小合同，任意硬限可能让合法长会话永久无法同步。需要与服务端限制对齐后处理。 |
| Client escort 双文件非原子提交 | 成立，`live/escort.rs::stash` 先写 bin 再写 json，崩溃存在孤儿 bin 窗口。仅把两个 write 改成 rename 仍不能让双文件事务原子，需定义统一容器或启动恢复/清理规则。本轮未改存储格式。 |

回归测试与限制：

- `cargo test -p rcode-agent --lib`：事件消费者消失时工具收到取消并完成异步清理；WebFetch 在分块 body EOF 之前拒绝超过 2 MiB 的内容，停滞读取可停止，大小写隐藏块不泄露且保留 Unicode 正文。
- `cargo test -p rcode-agent --test agent_management`：失败与停止两条路径的未读消息可观察，显式恢复按顺序投递；会话任务存储释放后输出文件清理。
- `cargo test -p rcode-mcp`：模拟 Python stdio 服务；握手/工具列表期限、工具副作用提交后的取消/超时、后续独立调用恢复，以及既有 HTTP/stdio 禁止重放与项目快照测试。
- `cargo test -p rcode-client --lib`：客户端既有交付/存储回归。M19 本次没有基准声明；改变的是阻塞 SQLite 的执行位置，没有声称 SQLite 本身加速。
