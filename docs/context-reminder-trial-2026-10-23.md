# 记忆与 MCP 内部提醒：第一轮真实模型实验

日期：2026-10-23。用户在完成 Claude Code / Peri 源码调查后提出开始试验。本轮实现独立实验原型并调用已授权的模型服务；没有把新策略接入 RCode 默认运行链路，没有创建提交。

后续用户确认接入项目后，已实现事实索引增量与 MCP 状态通知，详见 [当前实现](context-reminders.md)。MCP 指令正文仍保留在 system。本报告的数据继续代表接入前的独立实验，不冒充生产接入后的真实服务结果。

## 结论

- 明确事实索引的增量追加值得进入 RCode 集成试验：15 个场景的业务字段、工具参数和限定输出检查全部通过。
- MCP 指令增量在 9 个场景中业务字段全部正确，8 个满足限定输出；同名修改、断开撤销、重连、恢复和压缩都能识别当前值。但这只是合成服务指令，不能证明任意 MCP 指令降低消息角色后都保持同等优先级。
- 相同更新场景且返回相同后端标识的 4 组记忆请求中，增量组输入加权命中率为 **90.77%**，头部替换对照为 **16.13%**；未缓存输入从 44,902 降到 5,285 token，减少 **88.23%**。这是有限样本的观测结果，不是全会话命中率承诺。
- 完整记忆实验含冷启动、状态失效、压缩和路由切换，增量组总体命中率为 **75.14%**。不能用更新子集的 90.77% 代替这个累计值，也不能据此承诺稳定达到 99%。
- 本轮没有证明延迟改善。上述 4 组匹配请求的总耗时，头部对照约 17.0 秒，增量约 22.3 秒；网关路由与生成过程仍有干扰。

## 范围与方法

总共 66 次调用：3 次预检、63 次正式对照。请求模型统一为 `deepseek-v4.1-flash`，端点为用户提供的服务。预检中一条请求在 256 输出 token 用尽时只有推理、没有正文；正式组统一使用 1024，63 条均没有 `finish=length`。预检保留原始记录，不纳入正式统计。

实验复用此前由 RCode 生产 Harness 导出的 system 和 13 个工具定义，并加载当前 `crates/agent/src/memory_prompt.md`。额外添加固定的实验协议说明、40 条合成事实索引和 160 条无关背景记录。事实、路径、服务规则均为夹具，没有读取或上传真实记忆正文、项目源码或用户文件。

三种记忆布局：

| 布局 | 更新方式 | 说明 |
|---|---|---|
| head | 当前状态放在 system 末尾，每次更新替换它 | 使用相同实验状态协议的头部对照；不是完整 RCode 客户端端到端运行 |
| snapshot | 每次变化追加完整当前索引 | 比较完整快照的历史增长成本，不宣称这是 Claude 的原样实现 |
| delta | 首次完整基线，随后追加 upsert 与显式 remove | 无变化不重复追加；失效、恢复和压缩时提供完整新基线 |

记忆使用/保存规则始终保留在 system；实验迁移的只是明确事实和引用指针，没有迁移用户偏好或反馈型行为规则。MCP 指令放在独立实验域中，只比较 head/delta，不代表批准统一降为 user。

内部事件包含版本、来源、受众、域、修订号、replace/patch、状态、upsert/remove。结构化记录参考 Peri；历史中的内部 user 提醒参考 Claude；显式删除、同名内容比较与检查点校验是本轮原型自己的实现。未使用历史 system 消息、模型能力字段或 `in-history` 判断。

每个实验臂有不同的前置隔离标识，轮流改变调用顺序。各臂保留自己实际生成的历史与推理文本，使用 RCode Chat serializer 的 reasoning_content 形状。因模型回答和路由不同，后续历史长度并非完全相同；这是一组真实生成轨迹对照，不是单变量逐 token 的实验。

Read 场景中，真实模型必须生成正确的工具名和 file_path；工具执行由固定结果夹具模拟，再发给真实模型续答。没有运行真正的文件工具或 MCP 服务。

## 业务与格式结果

| 实验域 / 布局 | 场景数 | 业务字段或工具参数正确 | 限定输出通过 |
|---|---:|---:|---:|
| 事实索引 / head | 15 | 11 | 11 |
| 事实索引 / snapshot | 15 | 15 | 2 |
| 事实索引 / delta | 15 | 15 | 15 |
| MCP 指令 / head | 9 | 4 | 4 |
| MCP 指令 / delta | 9 | 9 | 8 |

“业务正确”要求输出对象的字段和值与预期完全一致，或 Read 工具与路径完全匹配。“限定输出”沿用最初判分：只允许请求的 JSON（接受外层代码围栏），不能额外解释。

初始严格判分为 40/63。复核发现 14 条只有额外解释，字段正确，因此另列业务判分 54/63，未覆盖或删除原始判分。snapshot 的额外解释及 MCP 冲突场景的解释均保留。小样本不能证明这些格式偏差由消息布局本身引起。

记忆覆盖：首次加载、不变、修正、新增、删除、读取失败状态、恢复、禁用状态、重新启用、检查点恢复、恢复后再修改、压缩、正文伪指令、按当前指针调用 Read、读取结果续答。

MCP 覆盖：首次加载、不变、同名内容更新、用户要求覆盖集成规则、断开并移除工具、重连并恢复工具、检查点恢复、压缩、工具 schema 改变。

头部对照的 9 次业务失败全部有保存请求可核对，主要是沿用旧值，另有一次区域值错误。离线分析从每条实际 requestBody 重建当前状态，63/63 与用例输入预期一致，因此这些失败不是测试期望与发送值不一致。它们也不能被直接称为 RCode 产品错误率。

## 缓存结果与路由限制

正式请求返回两种 model 标识：

- `vmc/deepseek-v4p1-flash-contributor-fallbacks`：44 次。
- `deepseek-v4.1-flash`：19 次。

同类请求在两种返回形态下的 input token 统计也不同。保留 responseModel、原始 usage 和分组结果；这些标识只说明服务返回了不同身份信息，不能独立验证真实上游供应商或其模型版本。

全部 63 条都有可观测缓存计数。比例采用 `sum(cached input) / sum(input)`；缺失计数仍应保持未知。下表是整段轨迹的观测统计，包含冷启动、工具目录变化、压缩、路由切换，不作为纯布局效应估计：

| 域 / 布局 | 总输入 token | 缓存输入 token | 未缓存输入 token | 加权命中率 |
|---|---:|---:|---:|---:|
| 事实索引 / head | 156,762 | 34,172 | 122,590 | 21.80% |
| 事实索引 / snapshot | 200,015 | 148,224 | 51,791 | 74.11% |
| 事实索引 / delta | 175,086 | 131,552 | 43,534 | 75.14% |
| MCP 指令 / head | 85,385 | 28,812 | 56,573 | 33.74% |
| MCP 指令 / delta | 89,442 | 53,348 | 36,094 | 59.65% |

事实索引增量组总输入比完整快照少 12.46%；其中既有事件尺寸差异，也有生成历史长度与路由统计差异，不能把全部减少归因于补丁格式。

进一步筛选记忆的 changed 场景，只保留 head 与 delta 返回相同后端标识的成对请求，剩余 correction、deletion、recovery、post-restore-edit 四组：

| 布局 | 输入 token | 缓存输入 token | 未缓存输入 token | 加权命中率 |
|---|---:|---:|---:|---:|
| head | 53,540 | 8,638 | 44,902 | 16.13% |
| delta | 57,265 | 51,980 | 5,285 | 90.77% |

匹配只控制当前请求返回的后端标识，之前的缓存预热路由仍可能不同，且只有四组，尚无重复试验或置信区间。

MCP 同名更新的增量请求命中 97.13%；头部请求为 0%，但两者返回的后端不同，不能把该差值全部归因于布局。断开移除工具时，增量组从前一请求的 98.41% 降至 31.29%，二者返回标识相同。schema 改动组两臂均为 0%，同时发生了后端标识切换，因此不能仅凭这组结果量化 schema 的独立影响。

## 生产接入前仍需处理的边界

1. **真实文件变化与分类。** 原型接收已准备好的事实条目，未解析真实 MEMORY.md，也未接入文件监听、工具写入或并发编辑。用户/反馈型规则仍不能自动归入事实数据。
2. **生产生命周期。** 检查点恢复、压缩是原型自己的确定性操作；还需接入 RCode 的实际存储、恢复、自动压缩、取消和重试。需要在调用失败/取消时决定事件是否已提交，避免丢失或重复。
3. **开关与错误。** disabled/unavailable 验证的是状态标记能否使旧索引失效，没有验证真实设置开关、停止记忆写入或全部规则卸载。不能用这个结果替代全局 memory=false 的产品验收。
4. **MCP 指令语义。** 仅验证了合成服务标签与一个冲突用例。真实指令可能包含工作流、权限或安全要求，仍需服务级测试和明确的来源/失效策略。schema 和工具集合应保持真实，不能为了缓存隐藏其变化。
5. **显示与持久化。** 原型有 model audience 与独立事件类型，但没有改桌面 UI。正式接入需验证内部提醒不成为普通用户聊天气泡，并能在恢复后原样回放。
6. **性能。** 缓存计数有改善，但总输入略增、延迟没有改善证据；需在真实会话分布中统计累计命中、未缓存输入和额外上下文开销。

建议优先把“事实索引 + 显式删除 + 无变化去重 + 恢复/压缩重建”作为一个窄范围集成候选。MCP 生命周期通知与 MCP 指令正文迁移分开评审；本轮结果不等于批准全部切换。
