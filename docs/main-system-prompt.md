# 主对话提示词

主对话参考本地 `D:\projects\claude-code` 的分层拼接方式，按当前需求精简为：固定基础正文 → 按需上下文 → 提供商分块。参考入口为 `src/constants/prompts.ts`、`src/constants/systemPromptSections.ts`、`src/utils/systemPrompt.ts`、`src/utils/queryContext.ts`、`src/utils/api.ts` 和 `src/services/api/claude.ts`。

RCode 使用自己的身份、工具和能力开关。基础提示词以用户编辑的 `docs/main-system-prompt.zh-CN-preview.md` 为准，运行时使用对应英文内容。沿用 Claude Code 的分层拼接机制，不要求保留其所有默认片段。Claude 的计费/认证字段、内部模型覆盖、实验性工具和其他产品专属能力不在 RCode 请求中声明。

## 默认片段

正文源文件在 `crates/harness/src/prompts/`，由 `include_str!` 编译进程序；修改后需要重新构建。`prompts.rs::PromptSessions::prepare` 按以下顺序生成片段：

| 区域 | 顺序与来源 |
| --- | --- |
| 固定区域 | `main.md` 基础介绍 → `harness.md` 与 `context.md` → `tasks.md` → `actions.md` → `communication.md` → `formatting.md` |
| 会话冻结区域 | 环境 → 日期 → 用户级 AGENTS.md 原文 → 项目级 AGENTS.md 原文 |
| 动态区域 | 开启时的记忆 → 已连接的 MCP 服务说明 |

基础内容仅包含身份、基础介绍、运行环境与工具约束、上下文管理、执行任务、谨慎执行操作、沟通方式、格式规则和运行环境。环境仅包含工作目录、是否为 Git 仓库、额外目录、平台和实际终端解释器五项。默认不再添加通用工具使用指引、会话指引、工具结果摘要规范、模型 ID、Git 状态或最近提交快照。工具的名称、参数和说明仍通过 API 工具定义提供，不重复写入基础正文。

记忆、MCP 和项目规范是独立的按需上下文，不属于这份基础正文。默认正文始终包含 Doing tasks，不再提供按输出风格删减基础段落的分支。

系统提示词从 `You are RCode, an interactive coding assistant.` 开始，不添加客户端标识文本。模式角色、语言偏好和输出风格的配置及拼接逻辑均已删除；回复语言和沟通方式遵循基础正文。

## 配置

每轮读取 `{data_dir}/prompt-settings.json`。调用方也可在 `RunRequest.modelOptions.prompt` 中传相同配置对象，覆盖文件中同名字段。未知字段、损坏 JSON 和错误字段类型会返回配置错误。

```json
{
  "cacheMode": "organization"
}
```

可用字段：

| 字段 | 行为 |
| --- | --- |
| `cacheMode` | `organization`（默认）、`global` 或 `tool-based` |
| `disableProjectInstructions` | 禁用项目规范自动加载，缺省 false |
| `additionalDirectories` | 显式额外目录，仅展示在运行环境中，不加载规范，也不改变文件访问权限 |

主对话始终使用固定基础正文，不再提供调用方追加或替换正文的入口。项目规范和日期属于 system 的会话冻结区域。

插件通过独立的贡献加载流程提供技能、子代理、钩子和 MCP 配置，不依赖主对话追加或替换正文。技能正文由技能工具按需返回，插件子代理使用其定义中的独立提示词；插件提供的 MCP 服务继续按连接状态提供工具和初始化说明。

## 会话快照与压缩

首次请求时生成版本化快照，保存身份、基础英文正文、环境、日期和用户级与项目级 AGENTS.md 正文。目录为 `{data_dir}/prompt-snapshots/<SHA-256(session ID)>.json`，文件名不使用原始 session ID。快照先写入同目录临时文件并同步，再原子提交且不覆盖已有文件；并发创建时使用已提交的同一份快照。读取限制为 2 MiB，损坏、未知版本和读写失败均返回错误，不静默覆盖。

同一 Harness session ID 的续聊、应用重启恢复和压缩后继续使用原快照。用户级或项目级 AGENTS.md 修改或基础提示词随程序升级变化时，仅新会话读取新内容。旧会话缺少快照时，在升级后首次运行创建。没有配置根目录的裸 Harness 只在内存中保存快照。快照绑定首次工作目录，恢复到其他目录会明确报错，要求新建对话。

手动和自动压缩不重建固定快照，也不重新扫描规范文件。最多缓存 128 个会话，淘汰后从磁盘恢复原快照。

记忆开关、MEMORY.md 索引和 MCP 连接说明每轮读取，位于固定会话内容之后；不会因它们变化重新读取两级规范。规范开关关闭时可抑制两级规范；首次运行关闭规范的会话没有保存规范正文，重新启用需新会话才能读取两级规范。`additionalDirectories` 仅作为运行环境信息，不再加载其中的规范。

## 自动记忆

设置中的“记忆”开关使用 `{config_dir}/agent-settings.json` 的 `memory` 字段，默认开启，每次运行读取。关闭时不创建或读取记忆目录，不注入记忆规则、索引及目录路径；普通文件工具仍遵循“信任所有”，不会因为关闭自动记忆而失去文件访问能力。已有对话历史不会因此被删除。

默认目录为 `~/.rcode/projects/<project-key>/memory/`。配置根目录遵循应用现有的 `RCODE_DATA_DIR` 设置，不随批量数据的 location 指针移动。`project-key` 是规范化项目根路径的 SHA-256 前 128 位十六进制值；Git 项目使用主仓库根目录，因此子目录、同一路径重复导入以及同一仓库的 worktree 共用记忆。普通文件夹使用自己的规范化绝对路径。它不依赖侧边栏 checkout ID，不会把不同路径的独立克隆自动合并。

```text
~/.rcode/projects/<project-key>/memory/
  MEMORY.md          索引，无 frontmatter
  user_role.md       独立记忆，包含 name/description/type 元数据
  feedback_shell.md
  project_goal.md
  reference_docs.md
```

只加载索引，不扫描并注入正文。索引最多 200 行、25,000 UTF-8 字节，截断时附提示。模型通过普通 Read、Write、Edit、Glob、Grep 工具按需读取和维护；保存需要写主题文件并更新 MEMORY.md，删除或重命名时也应维护索引。没有 MemoryWrite、团队记忆或 LocalMemoryRecall。

普通文件工具允许绝对路径和父级路径，使用宿主进程的权限，工作目录只用来解析相对路径，不是访问边界。旧的 `{cwd}/.rcode/memory/` 和 `{config_dir}/memory/` 文件不再自动加载；本次没有删除或自动迁移这些旧文件。

右侧边栏的空面板选择器与标签栏“+”菜单提供“记忆”入口，仅在项目所在设备的记忆开关开启时显示。列表通过 `ListProjectMemory` 从宿主配置目录读取，优先显示 MEMORY.md；点击文件复用现有编辑器，按 `memory: true` 的项目目标读写，保留保存、自动保存、文件监听和内容哈希冲突检查。入口跟随设置保存更新；刷新按钮重新读取列表。关闭开关不删除记忆文件或已打开编辑器中的草稿，用户仍可保存已打开文件。

## 两级 AGENTS.md 规范

首先读取固定的 `~/.rcode/AGENTS.md`，再读取绑定工作区根目录的 AGENTS.md。用户级路径由当前用户主目录解析，不受 `RCODE_DATA_DIR` 或配置/数据根目录影响；自定义数据目录中的 AGENTS.md 不作为用户级规范加载。只检查这两个精确位置，不向父目录查找、不递归子目录，也不读取 policy 或额外目录的规范。不加载 CLAUDE.md / CLAUDE.local.md、隐藏规则目录或隐式 @ 导入。

正文原样拼接，保留首尾空白与换行，片段之间增加两个换行。不添加 `<project-instructions>`、来源行或路径标题。同一个规范文件只加入一次，缺失/空白的文件省略。每份最多读取 32 KiB，超限追加截断标记；拒绝符号链接。

两级规范与日期均在 system 的会话冻结区域中，位于历史和当前用户消息之前，不进入聊天记录。普通文件工具不注入目录规范。规范开关同时控制两级。已有快照保持原内容；新的拼接方式适用于新快照。

## 提供商最终分块

模型请求携带结构化 `SystemPrompt`，保留身份、静态片段、会话冻结片段、动态片段和缓存模式，直到提供商适配器构造 HTTP body；主对话不设置客户端标识字段。兼容旧调用方的内部边界标记仍会被移除；主路径无需靠文本标记推断分段。

| 模式 | Anthropic system 文本块 |
| --- | --- |
| organization | 身份（组织级缓存）→ 静态正文与会话冻结区域（组织级缓存）→ 动态区域（不单独标记） |
| global | 身份（不缓存）→ 纯静态正文（全局缓存）→ 会话冻结区域（组织级缓存）→ 动态区域（不单独标记） |
| tool-based | 与参考项目跳过系统全局缓存的分支一致，系统块采用组织级缓存 |

全局模式仅应在提供商支持对应缓存 scope 时使用。系统和消息层共享最多 4 个 Anthropic 缓存点；关闭提供商缓存时不发送任何 `cache_control`。

OpenAI Chat Completions 将同一最终内容合并为首条 system 消息；OpenAI Responses 放入顶层 instructions，两者都不携带 Anthropic 缓存元数据。子代理、标题生成和摘要调用保持独立提示词。
