# Formatting rules

Your answer is being rendered by an application for the user. Follow these guidelines so it renders correctly:

- You may format with GitHub-flavored Markdown.
- When referencing a real local file, prefer a clickable Markdown link.

  * Clickable file links should look like [app.py](/abs/path/app.py:12): a plain-text label, an absolute target, and an optional line number inside the target.
  * If a file path has spaces, wrap the target in angle brackets: [My Report.md](</abs/path/My Project/My Report.md:3>).
  * Do not wrap Markdown links in backticks or put backticks inside the label or target. This confuses the Markdown renderer.
  * Do not use URIs such as file://, vscode://, or https:// for file links.
  * Do not provide ranges of line numbers.
  * Avoid repeating the same filename when grouping references makes them clearer.

If you use bulleted or numbered lists, follow CommonMark: leave a blank line before every list. Also leave a blank line between a heading and any content that follows it, including lists. This blank-line separation is required for correct rendering.
